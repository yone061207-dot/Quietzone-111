# QuietZone

A responsive classroom front-end prototype for reporting noise and misuse of campus study spaces.

## Run

Unzip the complete folder and open `index.html` in a current Chrome, Edge, Firefox, or Safari browser. No dependencies, build step, account, or server is required. For consistent local storage across browser sessions, use VS Code Live Server or serve the folder with `python -m http.server 8000` and visit `http://localhost:8000`.

## Files and screens

- `index.html`: Home, Report an issue, Track report, and Guidelines & FAQ screens, linked with `#home`, `#report`, `#track`, and `#guidelines`.
- `css/style.css`: shared responsive styling and sticky navigation.
- `js/script.js`: routing, mobile menu, validation, local reports, evidence preview, duplicate detection, and sample tracking.
- Illustration: inline SVG embedded in HTML; no remote image or font assets required.

This uses four distinct screens in one HTML document. The Module 8 separate-page directory is a typical structure example. If the instructor specifically requests separate HTML pages, confirm that expectation before submission.

## Prototype boundaries

All staff updates and sample locations are demonstration data. No staff are notified. New reports are stored in this browser only and remain Submitted. Photo previews do not store or upload image bytes. Follow-up email addresses use the explicitly labelled sample domains `@university.edu` and `@university.edu.ph`. Use fictional details. The FAQ provides a delete-local-data control. If browser storage is unavailable, records last only for the open session.

Sample references: `QZ-2026-0042` (On-site), `QZ-2026-0043` (Pending information), `QZ-2026-0044` (Resolved).

## GitHub submission

1. Create a GitHub repository using your own account.
2. Upload all project files while preserving the `css` and `js` folders. Do not upload only index.html from this folder.
3. Commit actual changes with a meaningful message, for example `Improve responsive navigation and report interface`.
4. Include the real repository URL in your BigSky submission. Ensure the instructor can access it.
5. Submit the project ZIP. Do not include `.git`, `node_modules`, credentials, or temporary files.

No repository URL or contribution history has been generated by this package. A solo student must confirm permission for an individual submission with the instructor. Do not fabricate collaborators or commits. The provided code was adapted with AI assistance; review it, understand it, and follow the course's attribution rules.

## Manual browser checklist

- Test all four screens at desktop, tablet, and phone widths (including 320 px).
- Scroll: the header stays at the top.
- Phone: open/close the hamburger; select a link; press Escape; check that navigation closes.
- Submit an empty form: errors appear. Fill a valid report: a local reference appears.
- Use a past date and a time within the sample library hours (07:00-23:00).
- Choose building, floor, zone, then seat; check recurring-pattern and space-misuse fields.
- Preview/remove a JPG/PNG; reject non-image or oversized evidence.
- Track a new local reference, an unknown reference, and all three sample references.
- Add information to the Pending information sample.
- Repeat a report for the same category/location within 30 minutes to check duplicate choices.
- Verify no horizontal overflow, readable labels, and keyboard access.
